# CLAUDE.md

Guidance for agents working in this repository. Player and maintainer documents are `README.md`
and `docs/` (GUIDE, SOURCE, RULES, TROUBLESHOOTING, POST-PATCH). That set is
complete; do not add documents.

## What this is

A local, offline web application that reads one No Man's Sky `.hg` save, shows every container,
lets the player route categories of item to containers, shows exactly what would move, and writes
the save only after proving it can do so safely. It moves what the player already has. No
spawning, no stat or unit editing.

Python 3.9 or newer, standard library only at runtime, no network access anywhere in the package.
One HTML document, one stylesheet, one script, no framework, no bundler.

## Data files

`nms_sorter/data/`: `items.json` (id to name, kind, category, subtitle, multiplier, bucket),
`buckets.json` (ordered taxonomy, including the generated `corvette_parts` bucket),
`stacks.json` (stack size per difficulty, group and kind), `savekeys.json` (obfuscated to plain
save keys), `vehicles.json` (exocraft types in `VehicleOwnership` order), `gridnames.json` (the
game's own word for each grid of a vessel), `DATA_VERSION` (game build and MBINCompiler pin) and
`DATA_COUNTS` (what a regeneration must produce; `tests/test_data.py` asserts a floor, not an
equality).

All of it is generated by `tools/gen_emit.py` from the game's own tables: paks read by
`tools/hgpak.py` (HGPAK v2 plus Zstandard), decoded by the pinned MBINCompiler, names from the
game's language tables. `--tables` with `--lang` is the only mode and both are required; the
base it merges over is the shipped data itself, so a run is read-modify-write and git history is
the only backup. Regeneration after a game patch is `docs/POST-PATCH.md`; additions are merged,
existing ids are never dropped. An id the table does not know is normal after a patch: it is
reported and left where it is.

## Invariants

**Write sequence.** `safety.apply_plan` runs one fixed sequence and refuses at the first failure:
lock beside the save; game state checked: closed, or running with the main-menu confirmation;
save gates; back up the save and its `mf_` and verify both; decode the backup copy; prove the
identity round trip on this file; transform; encode,
decode again, compare; prove nothing outside the named containers changed; check the `mf_`
format; temp file, fsync, atomic replace; patch the `mf_` sizes; re-read both files; settle the
manifest. The plan is re-planned from the exact bytes about to be written and its fingerprint
must match what was approved. `restore()` is the same shape in reverse and refuses when the game
has written since the apply. A change to `safety.py`, `codec.py`, `savemodel.py` or `planner.py`
must leave the written bytes identical for every existing test; a test pins this.

**Refused, not supported.** Apply off Windows; expedition saves; `mf_` formats other than 2004;
saves older than Waypoint (4.0); Game Pass, console and Switch saves. Refusing an unbuilt
permutation is the policy. Do not add support without a full test campaign.

**Version gate is advisory.** A save outside `savemodel.SUPPORTED_VERSIONS` plans with a banner
and applies with an info step; `strict_version_check` restores the refusal. Hard refusals are for
structural differences that were measured, never for a version number.

**Platform branching** lives in `platform.py` only.

**One error shape.** Every API error is `{error, kind, where?, ref?, steps?}` with a sentence a
player can act on. Every sentence the program can show is a `###` heading in
`docs/TROUBLESHOOTING.md`, verbatim; `tests/test_docs.py` enforces it.

**No internal names on screen.** Container keys, item ids, save keys and hashes go in tooltips
or code spans, never in visible prose. Labels come from the save or the game's own tables.

**Grids with no cells are not drawn**, not counted, not offered as destinations. A vessel is
owned when it has a hull, not when it has cells.

## Tests

```
python -m pytest tests -q                                       # Windows leg
NMS_SORTER_FAKE_PLATFORM=linux python -m pytest tests -q        # POSIX leg (pytest only)
python -m pytest tests -q --real-saves <a copy of a save folder>
python -m pytest tests/test_docs.py -q -s
```

Run all four before committing a change to the write path or to any player-facing sentence.
`--real-saves` must point at a copy. CI runs windows and ubuntu on Python 3.9 and 3.13, a
Hypothesis fuzz job, a docs job, and a release job on `v*` tags that builds the executables,
`SHA256SUMS`, the flat zip and the changelog section.

`tests/test_docs.py` also runs every `json` fence in RULES and GUIDE through migrate and
validate, bans em dashes and smart quotes, and follows every relative link. Rewording a message
means editing TROUBLESHOOTING in the same commit.

## Running it during development

Never launch the way a player would: a default launch opens the machine's browser and uses the
live settings and config. Every agent launch is:

```
set NMS_SORTER_NO_BROWSER=1
python -m nms_sorter --no-browser --log - --port <free port> ^
  --settings %TEMP%\<name>\settings.json --config %TEMP%\<name>\config.json ^
  --backups %TEMP%\<name>\backups --folder <copy of a save folder>
```

The test suite must never open a browser, and `tests/conftest.py` enforces that rather than
trusting the environment: a session-scoped autouse fixture replaces `webbrowser.open` for the
whole run and fails the session if anything was recorded, and the session sets
`NMS_SORTER_NO_BROWSER=1` so every test and every subprocess inherits the guard. Setting the
variable yourself before `pytest` is not what protects the run; it protects a server you start.

Never read or write the game's own save folder or the live `%LOCALAPPDATA%\NMS-Sorter\` state.
Test on copies. Never Apply anywhere except inside a temp copy. Stop your own server when done and
leave any other running sorter alone. Do not run the built executable for tests.

State at run time: `%LOCALAPPDATA%\NMS-Sorter\` holds `settings.json`, `config.json` with its
`.bak` and `before-reset` copies, `backups\`, `logs\`, and `runtime\` (the frozen build's
extraction directory). During a write a lock file and a temp file sit beside the save.

## Conventions

- Commit as `altmank <altmank@users.noreply.github.com>`. No real name, email or personal
  absolute path in any tracked file, fixture, comment or image.
- Do not commit or push unless asked. `TODO.md`, `design/` and `docs/MAINTAINING.md` (release,
  build and regeneration steps) are local and untracked.
- Docs are for a player or the maintainer. No contributor docs, no architecture or decision
  records, no review reports. Decisions live in commit messages and code comments. List
  deletions before making them.
- UI text is terse: no helper prose explaining the obvious, no emojis, no em dashes.
- Do not guess game facts. Names, orders and categories come from the save or the game's tables;
  when a table cannot be found, say so rather than hardcode.
- Refuse ambiguity: more than one candidate is an error, not a pick.
- Verify on the built page or artefact, with measured numbers, before reporting done.
